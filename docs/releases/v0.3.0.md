# Prime Agent WebUI v0.3.0 (`.3`)

This release promotes per-task rootless containers from a staged preview to the
validated DGX Spark production path.

## Highlights

- Dedicated `prime-runner` identity with subordinate UID/GID mappings and
  persistent rootless Podman state.
- Peer-authenticated abstract Unix task broker; the hardened WebUI API does not
  invoke Podman or cross identities itself.
- Six digest-pinned profiles: general, development, CAD, finance,
  network-operations, and review.
- Per-user Prime state/workspace isolation and recoverable per-user trash.
- Credential/model gateway for Nemotron, Qwen, and ChatGPT/Codex, including
  global fallback, per-user override, safe OAuth refresh, 401 retry, strict
  credential-file validation, and no credential mounts in task containers.
- Restricted, Internet-only, LAN/VPN, and confirmed full-network modes with
  server-side role policy and private-address enforcement.
- Read-only, capability-free, no-new-privileges containers with CPU, memory,
  PID, open-file, temporary-storage, and runtime limits.
- Live rootless steering, stop, resume, conversation persistence, Qwen routing,
  and accurate `Stopped` lifecycle status.
- Automatic root-only pre-migration recovery bundle plus checksum-validating,
  conversation-preserving rollback tooling.

## Security boundary

The dedicated broker permits the setuid `newuidmap`/`newgidmap` helpers and
bounds their available capabilities to `CAP_SETUID` and `CAP_SETGID`. It has no
ambient capabilities, hides `/home` and `/root`, and accepts only callers whose
kernel peer identity belongs to `prime-web`. The WebUI API retains
`NoNewPrivileges=yes` and `RestrictSUIDSGID=yes`; task containers drop all
capabilities and set no-new-privileges.

## Validation

- 51 Python security/policy/API tests (including the personal-credential
  fallback test added for this release)
- Nemotron, Qwen, and ChatGPT/Codex exact-response canaries
- Live WebUI task persistence, steering, stop, and resume canaries
- Temporary second-account catalog isolation and recoverable deletion
- Live container inspection confirming 8 GiB/4 CPU/256 PID limits, read-only
  root, no network, no-new-privileges, dropped capabilities, and owner-only
  mounts
- Restricted/public/private/LAN/full network policy canaries
- Recovery-bundle checksum and rollback dry-run validation
- Active-task catalog polling through Prime's temporary permission tightening,
  plus safe nonzero broker-exit failure reporting
