# Prime Agent WebUI v0.5.43

This release fixes a second cause of “Prime ended without answering after its
tool work.” Prime 0.9.5 can emit `agent_end` while it pauses to compact a long
conversation, then emit `compaction_start`, `compaction_end`, and another
`agent_start` to continue. The WebUI had closed the RPC input on the first
`agent_end`, interrupting that continuation. The affected tasks were near the
65K-token Nemotron context threshold; one log explicitly shows compaction
starting after `agent_end`.

The dashboard now keeps the task input open through that transition, shows
context-compaction progress, and waits for Prime to resume. If a task truly
ends after successful tool work without an answer, it queues one same-session
continuation that explicitly avoids repeating completed actions. Existing
Python parse-error correction remains limited to one attempt. A stalled or
unanswered continuation is still reported as failed, with the prompt retained.

The runtime stream reader now uses unbuffered reads, so multiple events arriving
together cannot remain hidden inside a buffered line reader. A subprocess
regression test reproduces the `agent_end` → compaction → resume sequence.
