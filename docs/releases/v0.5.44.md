# Prime Agent WebUI v0.5.44

Nemotron 3.5 Lightning's served context is raised to 262,144 tokens (256 Ki
tokens) while keeping its explicit FP8 KV pool at 2 GiB. At the new setting,
vLLM reports 505,783 cache tokens: one full-length request leaves 243,639
cache tokens, but two full-length requests need 524,288 and cannot run
concurrently. `MAX_NUM_SEQS=2` remains useful for shorter work.

The co-resident Qwen process now leaves less free GPU memory than the old
Nemotron `GPU_MEMORY_UTILIZATION=0.35` startup guard required. The recipe sets
that guard to `0.30`; the explicit 2 GiB KV allocation is unchanged. Both the
host Prime model catalog and the per-task OpenShell catalog advertise the new
context limit. The output ceilings remain 16,384 and 8,192 tokens respectively;
prompt plus reserved output must fit inside the served context.

On the live Spark, the endpoint advertised 262,144 and completed a
250,011-token synthetic prompt plus 16 output tokens in 73.89 seconds while
Qwen stayed healthy. Available system memory afterward was about 15.7 GiB
(~12%), below the project's earlier 15% headroom target; the reading was
already about 15 GiB before this change. Avoid overlapping long requests
until memory headroom is recovered or measured under the intended workload.
