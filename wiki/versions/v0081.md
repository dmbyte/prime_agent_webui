# Version v0081 — Production rootless task isolation

Date: 2026-08-26
Supersedes: [v0080](v0080.md)

## State captured

- Production WebUI tasks run as fresh rootless Podman containers under dedicated
  `prime-runner`, not the WebUI owner's Linux identity.
- A kernel-peer-authenticated abstract Unix broker validates each request and
  selects one of six immutable digest-pinned profiles. The WebUI API retains its
  no-new-privileges/setuid restrictions and never invokes Podman or sudo.
- The broker's rootless mapping exception is limited to `newuidmap`/`newgidmap`,
  a `CAP_SETUID`/`CAP_SETGID` bounding set, empty ambient capabilities, hidden
  home/root directories, and restricted address families.
- Every account has isolated Prime state and workspace. Containers have read-only
  roots, dropped capabilities, no-new-privileges, hard resource/time limits, and
  only owner state/workspace plus the chosen read-only gateway socket.
- The credential/model gateway serves loopback Nemotron/Qwen and ChatGPT/Codex
  without mounting credentials. Per-user OAuth overrides global fallback;
  ownership/mode/type/size/symlink checks and serialized refresh are enforced.
- Restricted, Internet-only, LAN/VPN, and full rootless network modes match role,
  execution, and confirmation policy. Internet blocks private destinations;
  LAN permits them; full is power-user/admin only.
- Existing conversations/skills/workspace were copied without deleting host
  originals. Live stop, steering, resume, recoverable delete, and conversation
  catalog behavior operate on isolated roots. A last-known-good per-user catalog
  keeps state polling available during Prime's temporary permission tightening,
  and nonzero broker exits produce a safe failed-task event.
- The repository contains automatic recovery capture, install/activate scripts,
  non-mutating rollback verification, a conversation-preserving rollback apply
  path, comprehensive rootless documentation, and v0.3.0 release notes.

## Verification

- 51 Python tests plus shell, Python, JavaScript, required-artifact, and release-
  version validation pass.
- Exact-response canaries pass for Nemotron, Qwen, and GPT-5.4 Codex.
- Live WebUI persistence/transcript, in-flight steering, stop, and resume pass.
- A temporary second account saw only its own conversation; `dbyte` could not see
  it. Its conversation was recoverably deleted and runtime files quarantined.
- Live inspect proved 8 GiB memory, 4 CPU, 256 PID, read-only root, no direct
  network, no-new-privileges, dropped capabilities, and owner-only mounts.
- Network canaries proved restricted denial, Internet public success/private 403,
  LAN private success, and full direct public success.
- All recovery manifest checksums and `rollback-rootless.sh --check` pass; no
  active or orphan task container remains.
- After final deployment, a restricted/no-tools production canary returned
  exactly `FINAL_ROOTLESS_OK`; active-task state polling stayed healthy,
  unauthenticated HTTPS remained 401, and all three production services were
  active.
