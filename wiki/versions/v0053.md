# v0053 — Prevent expired-session polling from banning clients

Date: 2026-08-25

The owner's LAN client was blocked after the old page generated repeated API 401
responses when v0052 invalidated Basic Auth state. All services and listeners
were healthy, and local HTTPS succeeded; Fail2ban's nftables set contained the
client address.

The filter now counts only failed `POST /auth/login` requests. The configuration
test passed, Fail2ban restarted active, the stale ban was removed, its nftables
set is empty, and client-side HTTPS again returns the expected 302 login response.
The 15-attempt/10-minute/one-hour reactive policy remains. No CIDR firewall policy
was added. ADR-0041 records the correction. This snapshot is immutable.
