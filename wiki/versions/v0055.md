# v0055 — Recover the reviewed authentication stack

Date: 2026-08-25

An unreviewed change replaced the loopback PAM session broker with an obsolete
dashboard server. That file attempted to bind `0.0.0.0:8765`, collided with the
native API, restarted continuously, and contained logic that accepted any
non-empty password even when PAM failed. Prime-specific PAM files had also been
changed to add `nullok`, and the obsolete Nginx PAM policy had been recreated.
The system-wide common PAM policies were unchanged.

All altered files and their checksums are preserved in the root-only recovery
directory `/var/backups/prime-auth-recovery-20260825T165500-0500`. The reviewed
broker and Prime PAM policy were restored from this repository; the backed-up,
unused Nginx PAM policy was removed. The broker is active only on
`127.0.0.1:8764`, invalid credentials return 401, the protected root redirects
to login, the login page returns 200, Nginx validates, Fail2ban has no active
ban, and both inference health endpoints return 200. Audited live WebUI, Nginx,
systemd, PAM, and Fail2ban artifacts match their tracked hashes. This snapshot is
immutable.
