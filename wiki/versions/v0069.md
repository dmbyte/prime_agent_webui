# v0069 — Add secure provider configuration workflow

Date: 2026-08-25

Settings now pairs a compact configured-provider filter with an **Add provider**
button. The modal catalogs the API-key, subscription, major cloud, and custom
OpenAI-compatible provider paths documented by installed Prime Agent 0.8.0 and
renders provider-specific fields.

Only administrators may read the catalog or submit configuration. Secret fields
are masked and write-only, cleared after submission, atomically stored in Prime's
mode-0600 auth/settings files, and never returned, logged, committed, or written
to the wiki. Existing OAuth credentials and local model definitions are merged,
not replaced. Subscription OAuth remains in Prime's Advanced-console `/login`.

The dashboard service remains loopback-bound behind authenticated Nginx, but its
systemd loopback-only egress filter is removed so native Prime children can call
configured providers. All 27 local tests and Python/JavaScript/shell syntax and
whitespace checks passed before deployment. Roll back to Git commit `e65b7a8` to
restore the prior UI/API/unit. This snapshot is immutable.
