# v0014 — Reverse-proxied WebSocket repaired

Date: 2026-08-23

Moved WebSocket origin enforcement from ttyd to Nginx. ttyd's internal
`--check-origin` compared the browser's external HTTPS origin with the reverse
proxy's loopback host, rejected `/ws`, and caused the reconnect loop. Nginx now
accepts only the approved HTTPS origins at `/ws`; ttyd remains loopback-only.

PAM-authenticated page and token requests returned 200. ttyd accepted a
WebSocket, spawned Prime, and maintained a client. A controlled live-browser
check found the active terminal input and no reconnect message. Nginx syntax,
services, models, bindings, browser health, and memory gate passed.

Rollback to the prior unit/site recreates the defect; v0008 is the useful
SSH-only functional rollback. This snapshot is immutable.
