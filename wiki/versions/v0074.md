# Version v0074 — Account-aware local trust boundaries

Date: 2026-08-26
Supersedes: [v0073](v0073.md)

## State captured

- A bounded regression correctly cleared the earlier argv, CSP, and guarded-
  import/listener false positives.
- The test still made an invalid single-user assumption and downgraded reachable
  privileged local services and shared execution identity to informational.
- The skill now treats user-influenced local processes, plugins, jobs, terminals,
  and agents as attacker-controlled when software exposes distinct accounts or
  roles. `localhost` and a shared OS identity are not authorization controls.
- Side-effect-free GET requests are not reported as CSRF data exfiltration without
  cross-origin response access, and absent HTTP method handlers are not assumed to
  dispatch into another method implementation.

## Recovery

Restore the v0073 `SKILL.md` from commit `c33518a` if this account-aware rule
misclassifies an explicitly mutually trusted deployment. No WebUI runtime or
security control changed.
