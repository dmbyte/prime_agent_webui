# v0051 — Security-harden Prime without CIDR firewall changes

Date: 2026-08-25

Prime now exposes only SSH and authenticated HTTPS beyond loopback. The default
HTTP site, NFS home export, NFS/rpcbind services, and wildcard Hermes listener
are disabled. PAM is restricted to the `prime-web` group; Nginx has throttling
and security headers; fail2ban provides reactive blocking. UFW remains inactive
and no new CIDR firewall policy was added, per owner direction.

The dashboard API now bounds concurrency and request types, serializes upload
quota and deletion operations, applies safer parsing/validation, emits structured
audit events, and runs with tighter compatible systemd protections. Local
security regression tests were added. One sensitive transcript was backed up
root-only and two credential-shaped key occurrences were redacted; external key
revocation remains the owner's account-level action.

All 19 pending security updates were installed. Local and deployed tests passed,
both models remain healthy/private with at least 20% memory headroom, all required
services are active, internal ports bind only to loopback, and no NFS exports or
security updates remain. The immutable pre-hardening bundle is
`/var/backups/prime-security-20260825T151200-0500`. ADR-0039 records the boundary.
